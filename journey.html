STEP 01 / REVEAL YOURSELF

Two prompts. One set of facts.

A / Weak prompt

Short and open-ended

Build me a personal website that looks modern and includes information about me.

It only specifies a modern personal website. It does not say which sections, features, contact methods, or tests are necessary.

Open Version A →
B / Strong prompt

Specific and verifiable

Act as a professional portfolio designer and web developer. Help me build a modern, interactive portfolio that I can share with companies and recruiters to showcase my skills, projects, education, interests, and career goals. Start by asking me questions about my background, technical skills, achievements, projects, and the roles I want to pursue. Use my answers to create a portfolio that reflects my personality while presenting me professionally. Organize the content into clear sections and highlight my strongest projects with their goals, my contributions, technologies used, and results where available. Create a unique visual identity with clean layouts, readable typography, smooth animations, and responsive design across mobile, tablet, and desktop. Make the portfolio easy to navigate and include working links and a clear way for recruiters to explore my work and contact me through a method I approve. Do not invent achievements, skills, experience, or results. Include only information I approve for public sharing and never expose sensitive personal details, credentials, or confidential information. Build a functional MVP rather than a static mockup. Before presenting the final version, test the main interactions, navigation, responsiveness, and content accuracy, fix any issues you find, and summarize what is ready to share and what still needs attention.

It defines the audience, portfolio sections, mobile support, working links, privacy restrictions, and testing expectations.

Open Version B →

Fair comparison: both versions present the same approved identity, education, Python, Java, HTML, CSS, VS Code, GitHub, SudokuLab, and career interests. Missing project details remain marked as unconfirmed, not invented.

STEP 02 / MAKE IT REAL

What improved—and why?

Content

Version B makes skills, the SudokuLab project, education and contact options easier to discover.

Direction

It explains interest in AI and web app development, along with the target roles provided.

Navigation

Sections are reachable through named anchors, with a mobile navigation menu.

Privacy

Only approved public details are used. No invented project metrics, certifications or employers.

These are differences in the implemented versions, not a claim that every strong-prompt requirement has passed browser or user testing.

STEP 04 / MAKE IT UNFORGETTABLE

Polish without making things up.

Implemented

  • Distinct dark visual identities for both versions
  • Responsive layouts and accessible focus indicators
  • Mobile navigation and reduced-motion support in the portfolio
  • Clear welcome screen with version selection
  • Side-by-side portfolio previews and a comparison page
  • This documented four-step journey

Still needs attention

  • Run and record a genuine blind test
  • Confirm SudokuLab features, personal contributions, repository URL and results
  • Do a final visual walkthrough on your own desktop and phone
  • Use the local preview; deployment is intentionally out of scope

Takeaway: The stronger prompt reduces ambiguity and defines acceptance criteria. A better prompt improves the instructions; it does not automatically guarantee a better result or replace testing.
